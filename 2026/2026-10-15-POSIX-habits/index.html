POSIX 习惯

“POSIX 习惯”通常指在编写 Unix/Linux 命令行程序、Shell 脚本或 C 程序时，遵循 POSIX（可移植操作系统接口）标准所形成的常见做法和约定。它既包含语法/接口层面的规范，也包含行为和风格上的惯例。

下面从几个常见角度来说明。

1. 命令行选项的习惯

POSIX 对实用程序的命令行参数有明确约定，最典型的是：

  • 短选项用单个 -，如 -a、-l。
  • 短选项可以合并：ls -la 等价于 ls -l -a。
  • 选项和选项参数可以分开或连写：
    • grep -e pattern
    • grep -epattern（部分实现支持）
  • -- 表示选项结束： 用来删除名为 -file 的文件。
  • 长选项通常用 --，如 --help、--version，但这更多是 GNU 习惯，不是严格 POSIX。

POSIX 还规定了一些标准选项含义，例如：

  • -f：force / file
  • -i：interactive
  • -r：recursive（但并非所有命令都这样）
  • -v：verbose
  • -n：no-op / dry-run / numeric

2. 退出状态码的习惯

POSIX 程序通常遵循：

  • 0 表示成功
  • 非 0 表示失败
  • 1 通常表示一般错误
  • 2 常用于用法错误（如参数错误）
  • >128 通常表示被信号终止（如 130 = 128 + SIGINT）

4. Shell 脚本中的 POSIX 习惯

如果写 #!/bin/sh 脚本，通常要遵循 POSIX sh，而不是 bash 扩展。

  • 使用 $(...) 而不是反引号（反引号也可移植，但 $() 更清晰）

5. 文件与路径习惯

  • 路径分隔符是 /
  • 隐藏文件以 . 开头
  • 临时文件常放在 /tmp，并使用 mktemp
  • 配置常放在 /etc
  • 用户配置常以 ~/.xxx 或 ~/.config/xxx 形式存在

6. 文本流与行习惯

POSIX 工具通常按行处理文本：

  • 每行以 \\n 结尾
  • 工具如 grep、sed、awk、sort、cut 都面向行
  • 没有输出时通常不报错，只是无输出

7. C 程序中的 POSIX 习惯

  • 使用 open/read/write/close 而不是只依赖 C 标准库
  • 检查系统调用返回值
  • 处理 EINTR
  • 使用 fork/exec 而不是 system
  • 信号处理使用 sigaction 而不是 signal
  • 头文件如 <unistd.h>、<fcntl.h>、<sys/stat.h>

8. “POSIX 习惯”常见的反面例子

  • 在 #!/bin/sh 里用 [[ ]]、数组、function、local
  • 把错误信息输出到 stdout
  • 成功时返回非 0，失败时返回 0
  • 不引用变量导致空格分词问题
  • 依赖 GNU 特有选项却声称可移植
  • 用 echo -e（POSIX echo 对 -e 的支持不一致）

总结

“POSIX 习惯”可以概括为：

  1. 接口可移植：使用 POSIX 标准定义的命令、选项、系统调用。
  2. 行为可预测：退出码、stdout/stderr、选项解析遵循约定。
  3. Shell 脚本克制：写 sh 就只用 POSIX sh 特性。
  4. 面向文本流：按行处理，支持管道和重定向。
  5. 错误处理明确：失败给非 0，诊断信息进 stderr。
