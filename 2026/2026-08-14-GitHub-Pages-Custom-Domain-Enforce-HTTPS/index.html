GitHub Pages 自定义域名使用 HTTPS

📝 笔记总结

子域名最好使用 CNAME 解析，不过有的就是无法使用 Enforce HTTPS 暂时未能解决，不如部署到其他服务商更为方便。

❌ 选项 Enforce HTTPS 勾不上

错误信息通常源于DNS解析记录类型与平台要求不匹配，导致系统无法正确识别并路由站点。

docus.shenjuexiao.com is improperly configured
Your site’s DNS settings are using a custom subdomain, docus-public.shenjuexiao.com, that is set up as an A record. We recommend you change this to a CNAME record pointing to shenjuexiao.com. For more information, see documentation (InvalidARecordError).

问题原因（InvalidARecordError）：域名 docus.shenjuexiao.com 当前在DNS设置中被配置为 A记录（即直接指向一个固定的IP地址）。大多数 SaaS 平台或托管服务要求自定义子域名必须使用 CNAME 记录，以便将流量指向服务商提供的特定域名（如 shenjuexiao.com）。

⚡ 解决方案

需要登录域名所在的DNS管理后台，将子域名的A记录删除，并新建一条CNAME记录。通常CNAME记录的目标值应填写为主域名或服务商提供的特定别名地址。

操作前的关键注意事项：

  • 确认目标地址：建议先检查平台后台（如 Vercel、Netlify 等）提供的具体 CNAME 目标值，以确保完全匹配。
  • 检查其他记录：如果该子域名下存在其他记录（如 TXT 或 MX ），需要确认是否需要保留，以免影响邮件或验证功能。
  • 生效时间：DNS 修改后通常需要几分钟到几小时不等才能全球生效，请耐心等待。

如果你不清楚具体的DNS管理后台在哪里，可以查看域名注册商（如阿里云、腾讯云、GoDaddy 等）的文档；如果不确定 CNAME 的具体目标值，建议检查当前托管平台（Netlify/Vercel 等）后台的 Domain 或 Site settings 页面。
